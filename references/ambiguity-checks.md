# 按需选择的歧义检查

这是内部检查参考，不是必答问卷。只检查能改变当前交付的事项，优先使用已有证据排除不相关项。

| 维度 | 可能存在的分歧 |
|---|---|
| 目标与范围 | 当前功能解决什么问题？哪些相邻能力属于本期，哪些只是未来设想？ |
| 角色与入口 | 谁可以操作？未登录、不同角色或不同设备的行为是否不同？ |
| 主流程与状态 | 操作成功如何表现？取消、重复点击、重新进入后是什么状态？ |
| 数据生命周期 | 数据归谁、存在哪里、保存多久？修改或删除关联内容时如何处理？ |
| 权限与可见性 | 谁可以看到、修改或共享？撤销权限后已有数据如何处理？ |
| 异常与恢复 | 失败、离线、部分完成或重试时会不会丢失内容、重复执行或重复计费？ |
| 既有产品兼容 | 老数据和已有入口是否需要继续工作？新规则是否改变已依赖的行为？ |
| 成本与约束 | 用户是否接受必要的持续费用、平台限制或维护负担？是否已有明确性能、隐私或无障碍要求？ |

## 示例：收藏功能

“支持收藏”没有决定账号同步、重复点击、原内容删除后的行为。若项目已有登录和账号数据，可推荐跟随账号同步，同时明确这是建议而不是用户已说过的要求。

可集中呈现：
> 我理解本期是添加、取消和查看收藏，不含分类与分享。收藏跟随账号同步。还需决定原内容删除后的行为：A. 收藏一起移除；B. 保留标题并显示已失效。我建议 B，避免用户误以为收藏丢失；它需要额外保留标题。你希望采用哪种？本期范围若有遗漏也可以直接纠正。

对应验收场景：原内容已删除 → 用户打开收藏列表 → 仍显示收藏标题和失效状态，无法打开原内容。只有在这一选择明确后，才把它写为已决定规则。

## 自查例子

- 用户要求把已定位的按钮文字从“提交”改为“保存”：不启动产品问卷或新建需求文件。
- 用户请求团队共享收藏：重点检查成员权限、可见范围和退出团队后的数据行为，不沿用个人收藏的默认规则。
- 用户没有回答存储位置的关键选择：保留待决状态，可继续查看已有存储实现，不自行当作已确认。
- 用户在清楚的推荐提案后说“按推荐做”：采用列明的推荐，继续已授权任务，不再例行询问同一决定。
- 用户只回答了三个问题中的两个：只保留剩余关键问题，不重复提问已解决项。
- 用户把约定的账号同步改成仅本地保存：更新存储、跨设备行为和验收场景，检查直接相关的登录依赖，无需重新询问无关规则。
